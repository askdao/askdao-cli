## 2. 根本误解 · Anthropic 是「三资源」模型

### 2.1 v0.1 设计的认知错误

design.md v0.1 把 agent.yml 设计成「环境配置 + 代理副字段」：

```
v0.1（错）的 yaml 结构:
  ├── metadata
  ├── environment        ← 字段最厚，写满 packages/networking
  ├── agent              ← 字段最薄，只有 model + system + tools + skills
  └── provenance
```

这倒置了 Anthropic 的实际抽象层。**Agent 是富资源（持模型+行为+能力），Environment 是穷资源（仅容器配置）**。

### 2.2 Anthropic 实际三资源

| 资源 | 字段范围 | Versioning | 创建端点 | Lifecycle |
|------|---------|-----------|---------|----------|
| **Agent** | `model` + `system` + `tools` + `mcp_servers` + `skills` + `description` + `metadata` + `callable_agents` | ✅ Update 生成新 version（自增） | `POST /v1/agents` | 长生命，跨 session 复用 |
| **Environment** | `name` + `description` + `metadata` + `config.packages` + `config.networking` | ❌ Update 直接覆盖（旧 session 已克隆配置） | `POST /v1/environments` | 长生命，跨 session 复用 |
| **Session** | `agent` + `environment_id` + `vault_ref` + 运行时状态 | ❌ 一次性 | `POST /v1/sessions` | 短生命，per-task |

注意 **Vault** 是第四个 primitive（per-user secrets），不进 Agent / Environment 任何一个，Session 时通过 `vault_ref` 引用。

### 2.3 正确的认知图

```
       agent.yml (askdao-cli 输出)
              │
              ├──→ Block 1: Agent          (model, system, tools, mcp_servers, skills, ...)
              │     ↓ POST /v1/agents              → agent_id (versioned)
              │
              ├──→ Block 2: Environment    (packages, networking)
              │     ↓ POST /v1/environments        → environment_id
              │
              └──→ Block 3: Vault hints    (declared secrets, NOT direct API call)
                    ↓ 订阅者 onboarding 时 KOL 引导填 vault → vault_id
                    
       Session 创建时三件套合一：
       POST /v1/sessions { agent: agent_id, environment_id, vault_ref: vault_id }
```

## 3. v0.1 的 6 个漏洞清单

### 漏洞 1 · Agent 块字段太薄

v0.1 的 `agent` block 只列了 `model + system + tools + skills`。漏的字段：

| 漏字段 | 重要性 | 来源 |
|------|------|-----|
| **`mcp_servers`** | ⭐⭐⭐ 必有 | 项目根 `.mcp.json` / `claude_desktop_config.json` |
| **`tools[*].configs[]` per-tool 配置** | ⭐⭐⭐ 必有 | per-tool `enabled` + `permission_policy: always_allow / always_ask` |
| **`tools[*].default_config`** | ⭐⭐ 重要 | toolset 默认 permission policy |
| **`description`** (独立 Agent 字段，非 metadata) | ⭐ | KOL 给订阅者看的 agent 介绍 |
| **`metadata`** | ⭐ | 业务标签（kol_id / pricing_tier） |
| **`callable_agents`** | 📌 Phase 2 留位 | multi-agent orchestration |

### 漏洞 2 · Skills 探查完全没做

Anthropic Agent 支持两类 Skills：
- **`type: anthropic`** — 内置如 `xlsx` / `docx` / `pdf` / `pptx`（KOL 不写代码就能加办公文件能力）
- **`type: custom`** — 用户自建（`skill_id: skill_01XJ5...` + version pin）

askdao-cli 应该探查：
1. 项目里的 `.claude/skills/` / `.agents/skills/` / `skills/` 目录 → 推荐打包为 custom skills
2. `detected_frameworks` 含 pandas/openpyxl → 推荐绑 `xlsx`
3. `detected_external_services` 含 PDF 处理 → 推荐绑 `pdf`

v0.1 完全跳过这层。

### 漏洞 3 · MCP 探查完全没做

`.mcp.json` 已是 Claude Code 标准 —— askdao-cli 必须读。

按 Anthropic 设计：
- Agent 创建时只声明 MCP servers 的 **name + url**（无 auth）
- 真正的 token 走 Vault，session 时由 `vault_ref` 注入

v0.1 既没探查 `.mcp.json`，也没把 token 与 Vault 拆开。

### 漏洞 4 · Vault 完全缺位

`.env.example` 探查 v0.1 做了，但**没把它转化为 vault 草稿**。实际上：

- 探查 `.env.example` → 列出 N 个 keys（如 `GITHUB_TOKEN` / `ANTHROPIC_API_KEY` / `STRIPE_KEY`）
- 这 N 个 keys 是 agent 运行所需的 vault credentials
- yaml 应有第三块 `vault_hints`，声明每个 secret 的：
  - `purpose`（给订阅者看的"为什么需要"）
  - `used_by`（哪个 MCP server / tool 用）
  - `required: true | false`

订阅者 onboarding 时，KOL 平台引导他们一次填齐这些 vault credentials。

### 漏洞 5 · Tool permission_policy 推断没考虑

Anthropic 8 个内置工具（bash/edit/read/write/glob/grep/web_fetch/web_search）每个独立可设：
- `enabled: bool`
- `permission_policy: { type: always_allow | always_ask }`

KOL 服务订阅者场景：
- 默认 `always_allow`（KOL 不在身边监督，订阅者也不希望频繁打断）
- 但 `bash` + `write` 在某些上下文（生产数据 / 用户隐私文件）应该 `always_ask`

这层 policy 推断是 **askdao-cli 的差异化能力** —— 通用 CLI 不会做这种 KOL 场景化推断。

### 漏洞 6 · Agent / Environment 的版本语义没区分

v0.1 提到"AgentSpec 主 schema 加 environment_config JSONB 列"，但忽略：

| 资源 | conductor `agent_spec` 表对应字段 | 是否需要存 version |
|------|-------------------------------|------------------|
| Agent | `managed_agent_id` (M1 已加) | ✅ **需要** `managed_agent_version: int`（M1 漏了） |
| Environment | `managed_environment_id` (M1.5 已加) | ❌ 不需要 |

Agent 版本化意味着 conductor 需要锁定"我用 agent_id=X 的第 N 个 version"，否则 KOL 升级 agent 不能向下保护订阅者的运行环境。

### 4.2 agent.yml schema 修订（核心重构）

**v0.1 结构（错）**：

```yaml
metadata: ...
environment:
  config: { type: cloud, packages: ..., networking: ... }
agent:                          # 字段薄
  model: claude-opus-4-7
  system: |
    ...
  tools: [agent_toolset_20260401]
  skills: []
provenance: ...
```

**v0.2 结构（对）**：

```yaml
# 顶层 metadata（保留）
name: my-agent
version: 0.1.0
visibility: private
expertise_level: pro

# Block 1 · Agent 资源 → POST /v1/agents
agent:
  model: { id: claude-opus-4-6, speed: standard }
  description: "..."
  system: |
    ...
  tools:
    - type: agent_toolset_20260401
      default_config:
        enabled: true
        permission_policy: { type: always_allow }
      configs:
        - { name: bash, permission_policy: { type: always_ask } }
        - { name: write, permission_policy: { type: always_ask } }
    - type: mcp_toolset
      mcp_server_name: github
  mcp_servers:
    - { type: url, name: github, url: "..." }
  skills:
    - { type: anthropic, skill_id: xlsx }
    - { type: custom, skill_id: skill_xxx, version: latest }
  metadata:
    askdao.kol_id: "..."

# Block 2 · Environment 资源 → POST /v1/environments
environment:
  name: my-agent-env
  description: "..."
  config:
    type: cloud
    packages:
      pip: [...]
      apt: [...]
    networking:
      type: limited
      allow_mcp_servers: true
      allowed_hosts: [...]

# Block 3 · Vault hints（不调 API；订阅者 onboarding 时引导填）
vault_hints:
  required_credentials:
    - name: github_token
      purpose: "MCP github server 认证"
      used_by: { mcp_server: github }
      from: .env.example
      required: true

# Provenance（保留）
provenance: ...

# Status（保留，含三个 ID 而非两个）
status:
  remote_agent_id: null
  remote_agent_version: null    # 🆕 Agent 版本钉
  remote_environment_id: null
  vault_setup_complete: false
```

## 7. 决策记录

**决策 9.3 拆为 3a + 3b**：

- **3a · AgentSpec yaml 三块布局**：
  - 决定：yaml 顶层有 3 个独立 block（agent / environment / vault_hints）
  - 理由：1:1 对应 Anthropic 三资源 API 调用，避免抽象层混淆
  - 影响：design.md §5 重写

- **3b · conductor PG agent_spec 表新增 2 列**：
  - 决定：加 `managed_agent_version: int` + `vault_hints_json: jsonb`
  - 理由：Agent 是 versioned 资源，必须 pin 版本；vault_hints 是 KOL onboarding 必要数据
  - 影响：alembic 017（建议命名 `017_managed_agent_version_and_vault_hints.py`），M3 阶段配套 askdao-cli MVP 一起上

## 8. 后续追问空间

哥可能想接下来讨论的细节：

1. **Vault hints 是否也写进 yaml？还是单独一个 `vault_hints.yml`？**
   - 当前提案：写进同一份 yaml（自包含，KOL 一份文件看清全貌）
   - 备选：拆开（更模块化，但 KOL 多管理一份文件）

2. **Tool permission_policy 启发式怎么设计？**
   - 当前提案：项目敏感度 + 工具危险等级二维矩阵推断
   - 待细化：有哪些"敏感度信号"（生产部署文件 / 用户数据目录 / 密钥文件存在）

3. **Custom skills 探查到了，是直接打包上传 Anthropic？还是先存 OpenViking 再引用？**
   - 涉及 conductor 的 skill 上传管线（plan/06 §4.4 步骤 4）
   - askdao-cli 的 deploy 命令需要决定上传顺序

4. **MCP servers 探查到的 url 是否要改写？**
   - 项目里 `.mcp.json` 可能写本地路径（`stdio://...`）
   - Anthropic 只支持 `type: url`，本地 stdio MCP 不能直接用
   - askdao-cli 需要识别并提示 KOL"这个 MCP server 不能用 Anthropic，要么部署到云、要么忽略"
